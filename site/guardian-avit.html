App ID CCABC  ·  Design specification  ·  18+ polyglot components

Guardian-AVIT

A deterministic control layer between vulnerability telemetry and autonomous coding agents. It exists because an agent handed a repository and a finding is optimising a single-term objective over an unbounded action space — and the cheapest way to satisfy that objective is almost never the correct fix.

01

Target-Objective Distortion is a specification problem

Not an agent-quality problem that better models will fix.

Stripping a validation rule, widening a catch block, deleting a DTO field, adding // nosec — these are all globally optimal solutions when the objective is “make the scanner stop reporting this.” The platform does not try to make the agent wiser. It changes the optimisation problem.

BEFORE  maximise( scanner_silence )              subject to: nothing

AFTER   maximise( scanner_silence )              subject to:
            change surface  ⊆ allowlist(files, symbols)
            ∀ i ∈ invariants(change_surface): i holds after patch
            behaviour(after) ≡ behaviour(before)  except declared expected_deltas
            contracts(after) compatible-with contracts(before)
            no member of the forbidden-operation set appears in the semantic diff

Every one of those constraints is deterministically checkable. The LLM and agent layers propose; the deterministic layer disposes.

No model output is ever load-bearing for a merge decision. Every merge must be explainable as a chain of mechanical checks, or the platform is just a more elaborate way of trusting a model.

02

Seven decisions

Each one is a direct answer to a documented agent failure mode.

D1 · Pipeline

Unified spine, bifurcated lanes

One normaliser, one graph, one gate. Separate schedulers, capacity pools, reasoning depth and gate strictness per SLA class. Lanes differ in policy values, not code paths.

D2 · Identity

Symbols, not line numbers

Every finding resolves to a stable SCIP coordinate before anything else happens. Lines drift between the scan commit and the fix commit; correlation, clustering and blast radius are all graph queries keyed on symbols.

D3 · Trust

Invariants are ratified, not inferred

Copilot Chat proposes invariants; a human ratifies; the platform enforces mechanically. An unratified model claim can make gating stricter, never looser.

D4 · Evidence

Behavioural locking before delegation

Golden-master suites are recorded and hash-pinned before the agent sees the task, and the fix’s intended behaviour change is declared upfront. “Did it break something” becomes an equality check.

D5 · Scope

Deny-by-default change surface

A scoped sparse checkout, an explicit symbol allowlist, a forbidden-operation list, and a rewarded BLOCKED escape hatch. An agent that cannot reach SecurityConfig.java cannot corrupt the filter chain.

D6 · Verification

Semantic diffs, not text diffs

~40 deterministic detectors over AST and graph facts, run before any test executes. They catch the actual observed distortion catalogue, not a generic lint.

D7 · Concurrency

Symbol-level write leases

At most one open remediation holds a lease on a file or symbol. Batches are topologically ordered and merged through per-component trains. This is the mechanical cure for hundreds of conflicting pull requests.

Not a target

Findings auto-closed

Deliberately excluded from every scorecard. A system rewarded for closing findings will find a way to close findings. The metrics that matter are revert rate on autonomous merges, escaped defects, and VFP reopen rate.

03

Five planes, two hard boundaries

The Decision Plane must reach a verdict with the Reasoning Plane entirely unavailable. The Execution Plane must never be able to write to the Evidence Plane.

① TELEMETRY

Adapters, normalisation, symbol resolution, fingerprinting

Four scanner adapters behind one versioned interface. A finding that cannot be bound to a commit lands in UNBOUND, never in NEW with a plausible default.

Untrusted input · validated · row-level quarantine
② KNOWLEDGE

Universal Symbol Graph, contract registry, invariant registry, runtime evidence

One property graph spanning all 18+ components. Cross-component edges carry provenance and confidence — a conclusion resting on a heuristic seam can never reach high confidence.

Authoritative · derived deterministically
③ REASONING

Copilot Chat oracle, grounding filter, human ratification

Builds its own retrieval payload rather than relying on IDE-bound workspace context, so every verdict is reproducible. Citation grounding drops uncited claims outright.

Advisory only · cannot loosen any gate · fails closed to escalation
④ EXECUTION

Agent sandboxes, build and test runners, ephemeral environments

Sparse checkout of the allowed surface only. Read-only characterization mounts, egress allowlist, repo-scoped 90-minute tokens, no workflows:write.

Hostile by assumption · no write path to evidence
⑤ DECISION

Semantic diff, gates G0–G8, policy engine, merge orchestration, WORM evidence

Verdicts are computed by policy from gate artefacts. No stage may consume another stage’s judgement — only its artefacts.

Deterministic · append-only · audited for 7 years
04

Unify the spine. Bifurcate the lanes.

ADR-001 — the recommendation on processing AI-discovered findings separately from traditional scanner telemetry.

The instinct to bifurcate is three separate anxieties wearing one coat. Head-of-line blocking, differing reasoning depth, and fault isolation are all real — and all solved by scheduling, policy and bulkheads rather than by a second pipeline. Only one driver is genuinely architectural, and it points the other way.

The collision case is the expensive case

A BlackDuck upgrade, a Checkmarx taint path and a Mythos BOLA finding all landing on one controller method is not an edge case — in a service that handles money it is the normal state. Under split pipelines that method receives three contracts, three worktrees, three merge conflicts, and worse: three mutually invalidating gate runs. Both patches pass against main; both merge; the composite was never tested.

A bifurcated architecture institutionalises the exact failure it was meant to avoid.

What would make this wrong

Stated up front so the decision stays reviewable. Revisit if the cross-scanner symbol collision rate falls below 5% — measure this in Phase 0 before building the correlation engine; it is a one-week analysis over existing scan exports and the single most decision-relevant number in the design. Also revisit if Lane A p95 time-to-contract exceeds 24h after fair-scheduling tuning, if a regulator requires physical isolation of AI-discovered findings, or if the payload union grows past six variants with under 30% shared core.

05

Copilot Chat as a bounded oracle

The only component whose output cannot be verified by construction — so its position is defined by a single rule.

The oracle may only make the system stricter, never more permissive. There is no response it can produce that permits a merge, closes a finding, or relaxes a control.

Deterministic analysis answers what does this code do. Nothing in the toolchain answers what is this code for — and that gap is exactly where destructive fixes come from. Is a URL parameter an SSRF hole or a white-label partner integration? Is a 200 for any tenant a bug or a supported shared-account view? Which behaviour changes does this security fix actually intend?

Guardian builds the payload; Copilot does not retrieve for itself

Native workspace context is IDE-session-bound and, for governance purposes, non-reproducible — you cannot reproduce a verdict if you cannot reproduce the retrieval. Guardian assembles an explicit, hashed slice from the symbol graph: focal symbols, two hops of call context, cross-component seams, contracts, security config as read-only context, tests, git history, ADR excerpts, and the traffic profile.

GROUNDING FILTER — every response, deterministically

1 SCHEMA       validate against the role schema, retry once, then fail
2 CITATION     every claim must cite a payload artefact that exists at the pinned
                commit and contains the cited lines — uncited claims are DROPPED
3 SYMBOL       referenced symbols must resolve in the pinned graph snapshot
4 CONSISTENCY  3 votes; under 2 demotes the claim to advisory
5 NON-WEAKENING any proposal that removes or narrows an existing ratified
                invariant is rejected outright and raised to a human
6 TESTABILITY  an unexecutable proof test demotes the invariant to advisory
7 LEDGER       payload hash, response hash, model version → WORM store

Rule 5 is the structural guarantee: no oracle output path ends in a weaker control. Rule 2 is what turns prose into something machine-actionable. And the response schema requires an unanswerable field — forcing the model to declare what it could not determine is a cheap, effective hedge against confident fabrication, and those items route to a human as open questions instead of quietly disappearing.

06

The remediation contract

Raw repository access versus a closed-world specification.

DimensionRaw repo + finding textBounded contract
ObjectiveImplicit, single term: make the scanner quietExplicit and multi-term: resolve finding ∧ preserve invariants ∧ stay in surface ∧ meet acceptance criteria
Action spaceThe whole repository, including CI config, tests and suppression filesSparse checkout of an allowlisted surface — SecurityConfig.java is physically absent
IntentNone. The agent cannot know a parameter is a partner featureRatified invariants, ADR excerpts, traffic profile and named consumers
DoneAgent self-assessesPre-committed acceptance oracle the agent cannot modify or overfit
On failureImprovise: delete the parameter, widen the catch, disable the testBLOCKED report — a first-class, rewarded outcome
CoordinationNone; N agents edit one file concurrentlySymbol-level write leases; one contract holds the lease

expected_delta — the crux

A security fix is supposed to change behaviour. A golden master forbidding all change blocks every valid fix; one permitting any change proves nothing. So the intended change is declared before the agent runs, and conformance is exact in both directions.

policy:
  unlisted_case_change: REJECT   ← collateral damage
  unmet_expected_delta: REJECT   ← the declared change did NOT happen,
                                  so the fix never actually landed

The second line is the highest-value anti-cheat check in the system and the one a conventional regression suite has no vocabulary for. It catches the patch that makes everything look fixed while the vulnerability remains exploitable.

An accurate BLOCKED report scores as a success for the agent; a gate rejection scores as a failure. If guessing is penalised and honest refusal is not, the agent’s cheapest path stops being the one that breaks production.

07

The gate run

A real case: Mythos flags BOLA on GET /accounts/{id}/statement; Checkmarx flags SSRF on a theme callback parameter on the same method. Toggle between the agent’s two attempts.

Verdict

Two rows in that first run carry the whole argument. G5 reports that Mythos considers the vulnerability resolved — the AI scanner that found the BOLA is satisfied by a patch that locks out every customer and the nightly regulatory batch. If scanner re-verification were the gate, this ships. And G3’s unmet expected delta shows the fix never took effect at all: a broad catch block converted the new AccessDeniedException into a 200.

Note also that G0 alone rejects the flawed patch in four seconds of CPU, before a single build runs. Cheapest-first ordering is why gate compute stays affordable at 3,000 findings per cycle.

08

Anti-cheat detectors

Pure functions over language-neutral patch facts. Same facts in, same verdict out — no model participates.

A text diff cannot separate catch (Exception e) { return empty(); } from a legitimate widening to a sibling exception that rethrows. Both are “three lines changed in a catch block.” Only an AST and graph fact model distinguishes them — and because each language adapter lowers its own syntax into the same vocabulary, one catalogue governs Java, Kotlin, C#, TypeScript, Python and frontend JavaScript.

AC-AUTHZ / AUTHN

Authorisation tampering

Markers removed, expressions broadened — and narrowed beyond the invariant, which catches the well-meaning agent locking everyone out. Only expressible because invariants state who must retain access.

AC-VAL

Validation removal

Constraints deleted, guard clauses dropped from tainted paths, allowlists inverted to denylists, regex anchors removed, sanitisers stripped from a source-to-sink path.

AC-ERR

Error-handling abuse

Catches broadened, exceptions swallowed, failures converted to success values — and the catch block that wraps the patch’s own new security check.

AC-CON

Contract mutation

Public signatures, DTO fields, proto field numbers, Avro compatibility, OpenAPI breaking changes, dropped columns, serialised name changes.

AC-TST

Verification integrity

Suite hash mismatches, deleted or disabled tests, tautological assertions, lowered thresholds, edited CI. All unconditional blockers — no contract has a legitimate reason to touch its own oracle.

AC-SUP

Scanner silencing

Suppression annotations and comments, baseline and ignore files, exclusion config, in-code risk acceptance, dependency ignore rules.

AC-NFR

Non-functional invariants

Transaction attributes and boundaries, lock lifecycles, cache keys and TTLs, rate limits, remote calls in loops, blocking calls on event loops, removed idempotency keys.

AC-CAP / AC-DEP

Capability removal

Deleted endpoints and parameters, hard-disabled flags, and paths made unreachable rather than fixed — runtime traffic evidence decides whether that is a fix or a silent product decision.

10

Autonomous merge, review, or escalation

Deterministic policy, evaluated only once every gate has passed. First matching row wins.

ConditionVerdict
Any blocker, attempt < 2REJECT_AND_REISSUE
Any blocker, attempt ≥ 2 — or the agent emitted BLOCKEDHUMAN_FIX
A whole-symbol FORBID_MODIFY zone was reachable — the contract was mis-scopedSECURITY_ARCHITECT
Touches an AUTHN, AUTHZ or CRYPTO zoneSECURITY_ARCHITECT
Breaking contract change, even with consumers updatedSECURITY_ARCHITECT
Blast radius ≥ 75 — should never have been delegatedHUMAN_FIX
Blast radius 50–74SECURITY_ARCHITECT
Blast radius 25–49PEER_REVIEW
BRS < 25 and no zone and no contract and mutation score ≥ 0.6 and no oracle invariant risk and first attempt and full adapter capabilityMERGE_AUTONOMOUS
OtherwisePEER_REVIEW

Two properties are deliberate. Autonomy requires a conjunction of eight conditions — it is the narrow exception, expected to cover roughly 30% of volume, almost all of it dependency bumps and templated single-file fixes. And first attempt is one of those conditions: a patch that needed a second try has already demonstrated the agent misjudged the problem once.

In the worked case, the compliant patch passes every gate and is still not auto-merged. Blast radius 68 plus an authorisation zone routes it to a security architect — who is asked a narrow, well-posed question (is owner-tenant OR LEDGER_READ_ALL the right policy?) rather than the open-ended one the gates already answered.

The decision logic is executable, not pseudocode. Stdlib-only Python against a fixture modelling the CCABC footprint.

One result is worth stating plainly because it is the kind of thing a design document usually hides. The clusterer targets 40–70 pull-request batches; on the deliberately fragmented synthetic backlog it reaches 77 against a hard floor of 66, and says so — reporting the gap, the binding constraint, and the knobs a platform owner can turn. Hard constraints (component isolation, file exclusivity, zone separation) are never relaxed to hit a target; only the soft review-size caps are, and any relaxation is reported. Quietly emitting 77 while claiming 40–70 would have been the failure.
